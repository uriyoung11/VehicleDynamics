# 11/5 작업 정리 — 데이터 확인, 원논문 재현, 합성 데이터 생성기

> 팀원용 요약. 자세한 수치는 [data_review.md](data_review.md)에 있다.

## 한눈에 보기

1. **받은 데이터 두 개(D1, D2)는 정상이다.** 다만 그대로 쓰면 안 되는 함정이 5개 있어서 정리했다.
2. **원논문(Spielberg 2019) 결과를 똑같이 재현했다.** 그리고 원논문 숫자가 "시험 문제 유출" 때문에 부풀려졌다는 것을 확인했다. 제대로 나누면 신경망 우위가 **33배 → 3배**로 줄어든다.
3. **합성 데이터를 만드는 시뮬레이터 1단계를 만들었다.** 물리 공식이 맞는지 테스트 5개로 검증했다.

## 1. 데이터 확인

### 왜 했나
남의 데이터를 받아서 바로 학습에 넣으면, 숨어 있는 문제 때문에 결과가 틀려도 모른다. 쓰기 전에 "파일이 멀쩡한지, 숫자가 말이 되는지"를 먼저 본다.

### 우리가 가진 데이터

| 이름 | 무엇 | 특징 |
| --- | --- | --- |
| **D1** | 원논문 데이터. 실제 승용차(VW GTI)를 마른 노면에서 몬 기록 20분 | 큰 차, 빠름(최고 33 m/s). 뒷바퀴는 거의 안 미끄러짐 |
| **D2** | 1/8 크기 RC카(F1TENTH)를 거칠게 몬 기록 52분, 타이어 4종 | 작은 차. 뒷바퀴가 크게 미끄러지는 구간(드리프트)이 많음 |

두 데이터가 서로 부족한 부분을 채워 준다. D1은 "진짜 차", D2는 "한계 주행(미끄러짐)"을 담당한다.

### 찾은 함정 5개 (꼭 알아둘 것)

| # | 함정 | 쉽게 말하면 | 어떻게 할지 |
| --- | --- | --- | --- |
| 1 | D1 정리본(`dry.npz`)의 분할 방식 | 0.01초 차이 나는 거의 같은 장면이 학습용과 시험용에 동시에 들어가 있다. **시험 문제가 미리 유출된 것과 같다** | 주행(한 번의 주행 기록) 단위로 나눈다 |
| 2 | D1 각 주행의 첫 0.1초 | 필터 때문에 속도가 0.9 → 14 m/s로 튀는 가짜 값이 있다 | 주행마다 앞 0.2초를 버린다 |
| 3 | D1 정리본의 Fxf 값 | 브레이크 밟을 때 원본과 값이 다르다. 앞바퀴 힘이 아니라 전체 제동력이 들어 있다 | 원논문 숫자 비교에만 쓰고, 우리 실험은 원본 파일로 통일 |
| 4 | D2의 `friction` 열 | 모든 줄이 0.6이다. 진짜 마찰계수가 아니다 | 파일별 진짜 값을 붙인다: hoons=0.65, xray=0.58, malarska=0.43, duck=0.45 |
| 5 | D2의 조향 | 전체 시간의 60%를 핸들을 끝까지 꺾은 상태로 달렸다 | 분석할 때 감안한다. 합성 데이터에도 이런 입력을 일부 섞지만 60%라는 비율까지 맞출 필요는 없다(운전 습관일 뿐) |

## 2. 원논문 재현

### 왜 했나
우리 프로젝트는 원논문을 출발점으로 삼는다. 출발점 숫자가 맞는지, 그리고 그 숫자를 믿어도 되는지부터 확인해야 한다.

### 한 일
- 원논문 코드는 2018년 TensorFlow 1 기반이라 지금 PC에서 안 돌아간다. 그래서 **PyTorch로 똑같이 옮겼다.** 모델 구조, 학습률, 배치 크기, 1500 에폭까지 원본과 같다.
- 원논문이 비교한 두 모델:
  - **물리 모델**: 타이어 공식(Fiala)을 쓴 자전거 모델. 데이터로 타이어 강성 2개와 마찰계수만 맞춘다.
  - **신경망**: 과거 0.04초(4시점)의 속도·조향·구동력을 보고 0.01초 뒤를 예측하는 128×2 MLP.
- 원논문 분할 그대로 한 번, **주행 단위로 다시 나눠서** 한 번 돌렸다(시드 3개).

### 결과: 실데이터 (오차, 작을수록 좋음)

| | 물리 모델 | 신경망 | 신경망이 몇 배 나은가 |
| --- | --- | --- | --- |
| 원논문 | 4.53e-5 | 1.34e-6 | 33.8배 |
| 재현 (원논문 분할) | **4.53e-5** | **1.35e-6** | 33.5배 |
| 재현 (주행 단위 분할) | 3.49e-5 | 1.11e-5 | **3.1배** |

- **재현 성공.** 물리 모델은 유효숫자 4자리까지, 신경망은 1% 차이로 같다.
- **문제 유출을 막으면 신경망 우위가 10분의 1로 줄어든다.** 처음 보는 주행에서는 신경망 오차가 8배 커진다. 그래도 신경망이 3배 낫다는 결론 자체는 유지된다.
- 발표나 보고서에서 "신경망이 물리 모델보다 30배 낫다"는 말은 쓰면 안 된다. **"주행 단위 분할 기준 약 3배"**라고 써야 한다.

### 결과: 합성 데이터 (원논문이 시뮬레이션으로 만든 데이터 5종)

| 데이터 | 물리 모델 (재현 / 원논문) | 신경망 (재현 / 원논문) | 신경망이 몇 배 나은가 (재현 / 원논문) |
| --- | --- | --- | --- |
| 기본 | 9.50e-10 / 9.51e-10 | 1.26e-5 / 9.94e-6 | 물리가 더 나음 (둘 다) |
| 하중 이동 추가 | 1.30e-4 / 1.30e-4 | 1.86e-5 / 1.52e-5 | 7.0 / 8.6배 |
| 타이어 반응 지연 추가 | 1.57e-3 / 1.57e-3 | 1.14e-5 / 9.42e-6 | 138 / 167배 |
| 노면 두 종류 섞기 | 3.12e-4 / 3.12e-4 | 6.96e-5 / 7.14e-5 | 4.5 / 4.4배 |
| 전부 | 1.09e-3 / 1.09e-3 | 8.24e-5 / 6.72e-5 | 13 / 16배 |

- 물리 모델은 다섯 개 모두 원논문과 같다.
- 신경망은 원논문보다 0~20% 오차가 크다(시드 1개). 어느 쪽이 이기는지, 대략 몇 배인지는 원논문과 같다.
- "기본"은 데이터를 만든 공식과 물리 모델 공식이 똑같아서 물리 모델이 사실상 정답을 맞힌다(오차 10⁻⁹). 이 실험은 비교로서 의미가 없다. 우리 합성 데이터를 시뮬레이터가 학습 모델보다 복잡하게 만드는 이유다.
- 타이어 반응 지연이 있는 데이터에서는 물리 모델이 앞바퀴 강성을 5~7k로 맞춘다(실제 150k). 물리 모델이 데이터에 없는 효과를 억지로 맞추면 파라미터가 엉뚱해진다는 뜻이다.

전체 표는 `repro/spielberg2019/results.md`, 그림은 `repro/spielberg2019/figure.png`에 있다.

## 3. 합성 데이터 생성기 (1단계)

### 왜 만드나
실데이터만으로는 안 되는 실험이 있다.
- **"처음 보는 노면에서도 잘 맞추나?"**: 마찰계수 μ를 마음대로 바꾼 데이터가 필요하다.
- **"타이어 힘을 정말 제대로 배웠나?"**: 실데이터에는 타이어 힘 정답이 없다. 시뮬레이터는 정답을 안다.

### 시뮬레이터란
3D 게임 같은 프로그램이 아니다. **차량 운동 공식을 Python으로 0.001초씩 계산하는 코드**다. 가상의 차를 랜덤하게 몰아서 주행 기록을 만든다.

### 한 일
- `physics/`: 차량 물리 공식. 단순한 것(P0)부터 복잡한 것(P2)까지 옵션으로 고를 수 있다.
  - P0: 타이어 힘이 미끄러짐에 비례(선형)
  - P1: 타이어 힘이 한계에서 포화(Pacejka 공식)
  - P2: P1 + 가속·제동 때 앞뒤 무게 이동 + 마찰 한계(마찰원)
- `data/synth.py`: 생성기. 한 번에 수백 개 주행을 동시에 계산한다.
  - 노면 μ를 주행마다 바꾼다. 학습용 0.3/0.5/0.7/1.0, 시험용 0.4/0.6/0.85(사이 값), 0.2(바깥 값)
  - 차 무게 ±10%, 타이어 강성 ±15%로 흔든다
  - 센서 잡음을 넣는다
  - 운전 방식 3가지(랜덤, 코너에서 가속, 코너에서 제동)와 핸들 끝까지 꺾기를 섞는다
- `data/loader.py`: 만든 데이터를 읽어서 학습 형식으로 바꾼다.
- 차량은 두 종류다. **풀스케일**(D1과 같은 차 수치)과 **소형**(D2와 같은 RC카 수치).

### 검증 (테스트 5개 모두 통과)
1. 복잡한 기능을 끄면 원논문 물리 모델과 같은 답이 나온다
2. 타이어 힘이 마찰 한계를 절대 넘지 않는다
3. 원을 그리며 핸들을 천천히 꺾으면 최대 횡가속도가 이론값(μ × 중력가속도) 근처다
4. 계산 간격을 반으로 줄여도 결과가 같다(계산이 정확함)
5. 생성 → 저장 → 읽기 → 학습 형식 변환까지 돌아간다

### 합성 데이터와 D2의 관계: "똑같이"가 아니라 "범위를 덮기"

합성 데이터는 D2를 흉내 내려고 만드는 게 아니다. μ를 바꾸는 실험, 타이어 힘 정답처럼 **실데이터로 못 하는 실험**을 하려고 만든다. 그래도 D2를 기준으로 보는 이유는 두 가지다.

1. **합성 데이터의 결론을 D2로 확인하려면 범위가 겹쳐야 한다.** 합성 데이터의 미끄러짐이 8°까지뿐이면, D2의 40° 구간에서도 같은 결론이 나올지 말할 수 없다.
2. **우리 연구 질문의 핵심이 포화(한계) 구간이다.** 뒷바퀴가 크게 미끄러지는 실데이터는 D2뿐이라, D2가 "한계 구간이 어디까지 가는지"의 기준이 된다.

그래서 맞출 기준은 하나다. **뒷바퀴 슬립각 30~40°까지 가는 주행이 일정량 있을 것.** D2의 비율(조향 60% 최대 등)이나 분포 모양까지 따라 할 필요는 없다. 오히려 평소 주행, 비선형 진입, 포화 구간을 고르게 넣는 편이 모델 비교에 낫다.

### 시험 생성 결과 (소형차, 128개 주행 × 20초)

| | 처음 | 수정 후 | D2 실데이터 (참고) |
| --- | --- | --- | --- |
| 일찍 멈춘 주행 (속도 저하) | 55개 | **2개** | - |
| 타이어가 한계(포화)에 있는 시간 | 13% | **41%** | - |
| 핸들을 끝까지 꺾은 시간 | 7% | 33% | 약 60% |
| 뒷바퀴 슬립각 (상위 1%) | 6.1° | 8.2° | 35~60° |

- 속도 문제는 해결했다. 목표 속도 하한을 올리고 저속에서 랜덤 가감속을 줄였다.
- 포화 구간 41%는 이미 충분하다.
- 부족한 건 **종류**다. 지금은 앞바퀴만 미끄러진다(언더스티어). 뒷바퀴가 미끄러지는 경우(오버스티어, 스핀 직전)는 차의 움직임이 전혀 다르고, 모델 간 차이도 여기서 가장 크게 날 것으로 본다.
- 일정이 빠듯하면 지금 데이터로 μ 일반화 실험(RQ3)부터 시작하고, 드리프트는 2단계에서 채운다.

### 남은 숙제
- **드리프트 재현**: RC카 드리프트는 모터 힘으로 뒷바퀴가 헛돌면서 생긴다. 지금 모델에는 바퀴 회전 계산이 없어서 이게 안 나온다. 2단계에서 바퀴 회전(D2의 `omega_wheels`, 모터 전류 `Iq`)을 넣는다. 또 스핀 판정 기준(차체 슬립각 30°)이 D2(최대 56°)에 비해 엄격하므로, 기준을 완화한 드리프트 전용 세트를 따로 만든다.
- 앞뒤 타이어 강성을 같게 둔 것도 언더스티어 원인일 수 있다. D2 차량 세팅을 확인해야 한다.
- 소형차 수치 중 무게중심 높이, 핸들 속도, 모터 출력은 임시로 넣은 값이다. D2 논문으로 확인이 필요하다.
- 다음 단계에 넣을 것: 타이어 반응 지연, 4륜 모델, 트랙 주행, 주행 중 노면 변화.

## 용어 풀이

| 용어 | 뜻 |
| --- | --- |
| 누수(leakage) | 시험용 데이터와 거의 같은 내용이 학습용에 들어가서 점수가 실제보다 좋게 나오는 것 |
| 주행 단위 분할 | 한 번 달린 기록 전체를 통째로 학습용 또는 시험용으로 나누는 것. 같은 주행이 양쪽에 섞이지 않는다 |
| 슬립각 | 바퀴가 향한 방향과 실제로 굴러가는 방향의 차이. 클수록 미끄러지는 중 |
| 포화 | 타이어가 낼 수 있는 힘의 한계에 도달한 상태. 더 꺾어도 힘이 안 늘어난다 |
| μ (뮤) | 노면 마찰계수. 마른 아스팔트 약 1.0, 빗길 약 0.5, 빙판 약 0.2 |
| MSE | 예측 오차의 제곱 평균. 작을수록 좋다 |
| 에폭 | 학습 데이터를 한 바퀴 다 보는 것 |
