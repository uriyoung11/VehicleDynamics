# MPC로 학습 모델 비교하기: 실험 설계 (11/16)

이 문서는 학습한 차량 모델(M0~M3, B1)을 MPC에 넣어 트랙을 달리게 하고, 그 주행 결과로 모델을 비교하는 실험 설계를 정한다(RQ5).
- MPC의 기본 개념, 사용 가능한 도구, 1단계 구현은 [mpc_plan_2026-11-12.md](mpc_plan_2026-11-12.md)에 있다.
- 이 문서는 **"무엇을 고정하고 무엇만 바꿀지"**와 **MPC를 쓰는 두 가지 방식**을 정리한다.

## 1. 원칙: 바뀌는 것은 학습 모델 하나뿐

우리가 학습시키는 것은 **차량 모델**이다. MPC와 트랙은 학습 대상이 아니다. 따라서 모델 비교가 공정하려면 **MPC, 트랙, 장면, 실제 차를 모두 고정하고 MPC 안의 예측 모델만 바꿔 끼워야 한다.** 주행 결과의 차이가 모델 차이에서만 나와야 한다.

```
            ┌──────────────── 고정 ────────────────┐
트랙·장면 ──► MPC (최적화기 + 비용 함수) ──► 조향·가속 ──► 실제 차 (P2 시뮬레이터)
                    │      ▲                                    │
                    ▼      │ 예측                               │ 상태
               예측 모델  ← 이것만 바꾼다 (M0, M1, M2, M3, B1)  ◄┘
```

### 고정하는 것

| 항목 | 고정 값 (현재) | 이유 |
|---|---|---|
| 최적화기 | MPPI. 후보 K = 256, 예측 H = 20스텝 × 0.05초 = 1초, 잡음 크기, 온도 λ | 탐색 능력이 같아야 한다 |
| 비용 함수와 가중치 | 아래 방식 A/B별로 한 번 정하고 고정한다 | 모델마다 가중치를 따로 튜닝하면 튜닝 실력을 비교하게 된다 |
| 트랙 | 개발용 트랙과 시험용 트랙을 미리 나눈다 (4절) | |
| 장면 | 출발 위치·속도, 노면 μ 지도(젖은 구간 위치·길이·μ), 주행 시간 | |
| 실제 차 | P2 물리(하중 이동, 결합 슬립), 1 ms RK4, 조향 각속도 제한, 출력 한계 | 모든 모델이 같은 차를 운전한다 |
| 차량 제원 | 학습 데이터를 만든 차와 같은 제원 (지금은 F1TENTH Xray 프리셋) | 다른 차로 시험하면 모델이 아니라 차 차이를 보게 된다 |
| Ux(종속도) 예측 | 모든 모델에 같은 물리식: dUx/dt = (Fx − 주행 저항)/m + r·Uy | 우리 모델은 [r, Uy]만 예측한다. 종방향은 공통으로 둬서 횡방향 차이만 보이게 한다 |
| 조작 한계 | 조향각·조향 속도 한계, 종방향 힘 한계 (μ_lim) | |
| 난수 | MPPI 잡음 시드 목록 (예: 0~4) | 샘플링 MPC는 시드에 따라 결과가 흔들린다. 같은 시드 목록으로 평균을 낸다 |
| 계산 예산 | 실시간 제한 없이, 같은 K·H로 매 스텝 끝까지 계산한다 | 모델 크기는 약 19.5k로 같아 계산량 차이가 작다. 계산 시간은 따로 기록만 한다 |

### 바꾸는 것

| 제어기 이름 | 예측 모델 | 역할 |
|---|---|---|
| `mppi_m0` ~ `mppi_m3` | 학습 모델 M0~M3 | 비교 대상 |
| `mppi_b1` | B1 (Fiala 물리, 계수 학습) | 물리 기준선 |
| `mppi_dry` | P2 물리, μ는 마른 노면 값만 안다 | "μ를 모르는 물리 모델" 기준선 |
| `mppi_oracle` | P2 물리, 젖은 구간 μ까지 안다 | **상한선.** 실제 차와 같은 모델이라 MPC가 낼 수 있는 최선이다 |
| `pp` | 없음 (pure pursuit + 속도표) | 참고용. 지금 시각화 영상의 제어기다 |

- 학습 모델은 모두 같은 데이터, 같은 체크포인트 규칙으로 학습한 것을 쓴다. 지금은 `checkpoints/<데이터>/<모델>_s<시드>.pt`이다.
- 학습 시드 5개를 모두 돌려, 학습 시드에 따른 편차도 결과에 포함한다.

## 2. MPC를 쓰는 두 가지 방식

### 방식 A: 속도 프로파일 추종 (경로 추종)

**MPC 입력:** 현재 상태, 트랙 모양(중심선, 폭), **목표 속도 프로파일**

**비용:** 중심선 횡오차² + (속도 − 목표 속도)² + 가장자리 접근·이탈 벌점 + 조작 변화량

**목표 속도 만드는 법:** 곡률과 μ로 미리 계산한다.

```
v_ref(s) = min( v_max, √( k · μ_가정 · g / |κ(s)| ) )   → 가속·감속 한계로 앞뒤를 다듬는다
```

- Spielberg 2019 설정은 k = 0.9 (`speedMu = roadMu * 0.9`, D1 공개 코드)이다.
- 모든 모델에 **같은 v_ref**를 준다.

**학습 모델이 영향을 주는 곳:** 정해진 속도에서 조향과 가감속을 어떻게 할지. 즉 "그 속도로 이 커브를 돌 때 차가 어떻게 움직이나" 예측의 정확도다.

**모델 차이가 드러나는 지표:** 중심선 횡오차, 트랙 최소 여유, 이탈 시간, 스핀 여부. 랩 타임은 모두 비슷하다(속도가 정해져 있으므로).

| 장점 | 단점 |
|---|---|
| 기준 논문(Spielberg 2019, Deep Dynamics의 MPC 실험)과 같은 구조라 비교하기 쉽다 | **얼마나 한계에 가깝게 달릴지를 사람이 정한다(μ 가정, k).** 학습 모델이 한계를 아는지는 드러나지 않는다 |
| 지금 코드로 바로 할 수 있다 | μ 가정이 틀리면(젖은 구간) 좋은 모델도 과속 지시를 받는다. 11/12 어려운 장면에서 정답 μ를 아는 MPC까지 스핀한 원인이다 |
| 안정적이고 해석하기 쉽다 | 새 트랙마다 속도 프로파일을 새로 계산해야 한다 |

### 방식 B: 진행 최대화 (MPCC형)

**MPC 입력:** 현재 상태, **트랙 모양(중심선, 폭)뿐.** 목표 속도는 없다.

**비용:** −(1초 동안 중심선을 따라 전진한 거리) + 가장자리 접근·이탈 벌점 + 조작 변화량 (+ 약한 중심선 횡오차)

**학습 모델이 영향을 주는 곳:** **얼마나 빨리 갈지까지.** MPPI는 모델이 "트랙을 벗어나지 않는다"고 예측한 후보 중 가장 멀리 간 것을 고른다.
- 모델이 접지력을 정확히 예측하면 한계 바로 아래로 달린다.
- 과대평가하면 과속해서 이탈하고, 과소평가하면 느리게 달린다.

**모델 차이가 드러나는 지표:** 랩(구간) 시간, 이탈 시간과 거리, 스핀 여부, 그리고 **예측과 실제의 차이**(MPC가 계획한 궤적과 실제 궤적의 오차).

| 장점 | 단점 |
|---|---|
| **한계를 학습 모델이 정한다.** "좋은 모델이 더 빠르고 안전하게 달린다"를 직접 보여준다 | 비용 가중치 튜닝이 까다롭다. 너무 공격적이면 모든 모델이 이탈한다 |
| 새 트랙에서 트랙 모양만 있으면 된다. 우리 목표("학습 때 못 본 트랙")와 맞는다 | 모델이 틀리면 공격적으로 실패한다. 안전장치 없이 결과만 비교하는 실험용이다 |
| 실차 레이싱 학습 MPC 논문(Kabzan 2019, ETH)과 같은 구조다 | 아직 구현하지 않았다 |

**학습 모델이 속도(Ux)까지 예측해야 하나? → 아니다.**
- MPC가 정하는 것은 가속·제동 명령(Fx)이고, 속도는 공통 물리식으로 계산한다. 모든 모델이 같다.
- 빠른 후보일수록 학습 모델이 "바깥으로 밀린다(r 부족, Uy 증가)"고 예측하면 가장자리 벌점을 받는다. 그래서 "이 속도로 돌 수 있나"라는 판단은 **횡방향 예측(r, Uy)에서 나온다.**
- 한계: 제동·가속 마찰 한계(`mu_lim`)는 학습 모델이 아니라 MPC에 고정값으로 들어간다. 그래서 젖은 구간에서 브레이크가 덜 먹는 것은 모델이 반영하지 못한다.
  - 기본은 모든 모델에 같은 마른 노면 값으로 고정한다(공정성, Spielberg 형식 유지).
  - 모델이 Ux도 예측하게 하는 확장은 모델 출력과 기존 결과를 모두 다시 만들어야 하므로 나중 과제로 둔다.

### 두 방식 모두 MPC와 트랙을 고정할 수 있다

| 고정하는 것 | 방식 A | 방식 B |
|---|---|---|
| 최적화기, 비용 함수와 가중치, 트랙, 장면 | 고정 | 고정 |
| 공통 Ux 물리식, `mu_lim`, 조작 한계 | 고정 | 고정 |
| 목표 속도 프로파일 | **모든 모델에 같은 것 하나** (같은 μ 가정으로 한 번 계산) | 없음 |
| 바뀌는 것 | 예측 모델만 | 예측 모델만 |

"MPC를 고정한다"는 알고리즘과 설정이 같다는 뜻이다. MPC가 내는 조향과 가속은 모델마다 다르고, 그 차이가 우리가 보려는 결과다.

### 두 방식 비교

| | 방식 A: 속도 추종 | 방식 B: 진행 최대화 |
|---|---|---|
| 속도를 정하는 쪽 | 사람 (μ 가정 × k) | MPC (학습 모델의 예측을 근거로) |
| MPC 입력 | 상태 + 트랙 + 목표 속도 | 상태 + 트랙 |
| 묻는 질문 | 같은 속도에서 누가 더 정확히 달리나 | 누가 더 빠르면서도 안전하게 달리나 |
| 주 지표 | 횡오차, 최소 여유, 이탈 | 구간 시간, 이탈, 스핀 |
| 기준 논문 | Spielberg 2019 (D1), Deep Dynamics | Kabzan 2019, Liniger 2015 |
| 상태 | 구현됨 (`control/mppi.py`의 `TrackCost`) | 구현 예정 |

**권장: 두 방식을 모두 돌린다.**
- A는 기준 논문과 같은 조건의 비교다.
- B는 우리 핵심 주장인 "학습 모델이 μ를 모를 때도 한계를 알아서 달린다"의 근거다.
- 발표용 영상은 B가 더 직관적이다. 같은 장면에서 모델마다 속도와 주행선이 달라진다.

## 3. 공정성을 지키는 절차

1. **비용 가중치는 개발용 트랙에서 `mppi_oracle`로 한 번 튜닝하고 고정한다.**
   - 정답 모델로 "트랙을 벗어나지 않으면서 가장 빠른" 가중치를 찾는다.
   - 학습 모델로 튜닝하지 않는다. 특정 모델에 유리해진다.
2. **시험용 트랙에서는 아무것도 바꾸지 않는다.** 결과를 본 뒤 가중치를 고치면, 고친 뒤 모든 모델을 다시 돌리고 그 사실을 기록한다.
3. **모든 제어기를 같은 장면, 같은 MPPI 시드 목록으로 돌린다.** 표에는 평균 ± 표준편차를 적는다.
4. **실패도 결과다.** 스핀이나 이탈로 주행이 끝나면 그 시점과 이유를 기록하고, 평균에서 빼지 않는다.
5. **학습 지표와 주행 지표를 같이 적는다.** 1초 롤아웃 nRMSE와 주행 결과가 같은 순서인지 본다(RQ5의 핵심 질문).

## 4. 트랙과 장면

### 학습 모델에게 모든 트랙은 처음 보는 트랙이다
D3 학습 데이터는 트랙이 아니라 무작위 조작(조향·가속 패턴) 주행으로 만들었다(`data/synth.py`, mode = random 등). D1과 D2도 각자의 시험장 데이터다. 그래서 **학습 모델 입장에서는 어느 트랙이든 처음 보는 트랙이다.**
- 모델이 새 트랙에서 잘 달리려면 트랙을 본 적은 없어도 된다.
- 대신 **트랙에서 겪는 상태(속도, 슬립각, μ)를 학습 때 본 적이 있어야 한다.**

### 그래서 트랙을 나누는 이유는 MPC 튜닝 때문이다
개발용 트랙에서 MPC 가중치를 맞췄으므로, 시험용 트랙은 **MPC 튜닝이 특정 트랙에 맞춰지지 않았는지** 확인하는 역할이다.

| 용도 | 트랙 (안) | 비고 |
|---|---|---|
| 개발 (가중치 튜닝) | Spielberg | 지금 쓰는 트랙. `data/tracks/` |
| 시험 | 다른 트랙 2~3개 | [TUMFTM racetrack-database](https://github.com/TUMFTM/racetrack-database)에서 고른다. 중심선과 폭이 같은 형식이다. 고속 코너가 많은 곳 1개, 헤어핀이 많은 곳 1개를 권장한다 |

트랙은 F1TENTH 크기로 축소해서 쓴다. 지금 Spielberg도 F1TENTH 크기 제원으로 달리고 있다.

### 장면 (노면 μ 지도)

| 장면 | μ | 묻는 것 |
|---|---|---|
| S1 마른 노면 | 전 구간 0.7 | 기본 주행 능력 |
| S2 젖은 구간 (학습 범위 안) | 한 구간 0.55 (D3 학습 μ 0.3~1.0 범위 안) | 모르는 μ 변화에 대응하나 |
| S3 젖은 구간 (학습 범위 밖) | 한 구간 0.2 | 학습 때 못 본 μ에서 어떻게 되나 |

- 젖은 구간 위치는 트랙마다 "가장 빠른 코너 진입부"로 같은 규칙으로 정한다(`run_scene.scenario`).
- 방식 A의 목표 속도는 마른 노면 μ로 계산한다. 젖은 구간을 모르는 현실 조건이다.

## 5. 지표

| 지표 | 정의 | 방식 |
|---|---|---|
| 최소 여유 | 주행 중 트랙 경계까지 가장 가까운 거리 (음수면 이탈) | A, B |
| 이탈 시간 / 최대 이탈 거리 | 트랙 밖에 있던 시간과 가장 멀리 나간 거리 | A, B |
| 스핀 | Ux < 0.3 m/s 또는 β가 일정 값 초과로 주행 종료 | A, B |
| 횡오차 RMS | 중심선(또는 목표 경로)과의 거리 | A |
| 구간 시간 / 평균 속도 | 같은 시작점부터 같은 끝점까지 걸린 시간 | B (A는 참고) |
| 예측 오차 | MPC가 계획한 1초 궤적과 실제 1초 궤적의 위치 차이 | A, B |
| 계산 시간 | MPC 한 번 계산하는 시간 | 기록만 한다 |

이 중 최소 여유, 이탈, 스핀, 계산 시간은 `control/run_scene.py`의 `metrics`에 이미 있다.

## 6. 현재 상태 (11/12 1단계 결과)

- **스핀**: 차체 미끄러짐각 > 30°로 속도가 0.3 m/s 아래로 떨어진 경우
- **멈춤**: 미끄러짐각이 작은데 MPC가 제동해서 멈춘 경우. 모델이 "어느 후보로 가도 위험하다"고 예측하면 진행 보상보다 벌점 회피가 커져서 멈춘다

**읽은 것**
1. **방식 B는 모델 차이를 크게 드러낸다.**
   - 정답 μ MPC만 완주했다. 젖은 구간 앞에서 미리 7 → 3.9 m/s로 감속했다.
   - 마른 μ만 아는 MPC는 늦게 감속하고 탈출에서 다시 가속하다 스핀했다. "목표 속도 없이 모델이 속도를 정한다"는 설계가 의도대로 동작한다.
2. **방식 A에서도 학습 모델 일부(M0, M1, M3)가 젖은 구간 코너에서 스핀했다.** 같은 목표 속도에서 물리 모델(마른 μ)은 완주했다. 학습 모델의 예측 오차가 MPC의 조향을 흔든 것으로 보인다.
3. **학습 모델은 방식 B에서 모두 실패했다.** 실패 방식은 서로 달랐다: 스핀(M1, M2), 과도한 보수성으로 멈춤(M0), 코너 진입에서 이탈(M3, B1).
4. **오프라인 지표 순위와 주행 순위가 다르다.** 1초 롤아웃 nRMSE로는 D3에서 M3가 가장 좋았지만, 주행에서는 A·B 모두 실패했다. M2는 A에서 완주했다. RQ5("롤아웃 정확도가 제어 성능을 예측하는가")에 대한 첫 신호지만, 아래 한계 때문에 결론으로 쓰기 이르다.

**한계 (결론 전에 해결할 것)**
- **학습 데이터 속도 범위:** D3 trial의 목표 속도가 1.5~6 m/s인데, 장면은 7 m/s로 달린다. 학습 범위 밖 속도에서의 실패일 수 있다.
  - 대책 1: 장면 속도 상한을 6 m/s로 낮춘다.
  - 대책 2: 속도 범위를 넓힌 D3로 다시 학습한다.
- **시드 1개, trial 데이터(23분):** 학습 시드에 따른 편차가 모델 간 차이만큼 크다(models_m1_m3.md). 시드 5개와 전체 D3로 다시 돌려야 한다.
- **MPPI 시드 1개, 장면 1개:** 샘플링 MPC는 시드에 따라 결과가 흔들린다. 시드 5개와 트랙 2~3개가 필요하다.
- **가중치 미튜닝:** 방식 B 가중치(w_prog 20 등)는 정답 μ MPC가 완주하는지만 확인한 첫 값이다. 3절 절차대로 튜닝하고 고정해야 한다.
- 계산이 느리다(배터리 전원에서 MPC 한 번에 0.8~2.9초). 전체 실험 전에 묶음 처리나 GPU를 검토한다.

**진단: 방식 B 실패가 제동 한계 설정 탓인가? → 아니다**
- 학습 모델은 MPC 안에서 제동·가속 한계를 마른 노면 μ 0.7로 가정한다(`mu_lim`). 그래서 젖은 구간에서 제동을 과대평가하는 것이 실패 원인일 수 있었다.
- 진단: 학습 모델의 종방향 힘 한계만 정답 μ 지도로 자르고(`--long-mu-oracle`, 결과 `*_B_longmu.npz`) 방식 B를 다시 돌렸다. 횡방향 예측은 그대로 모델이 한다.

2. **여유 계수에 따른 경향이 없다.** k를 올리면 실패가 늘어야 하는데, 결과가 들쭉날쭉하다(M1: 0.70 완주 → 0.75 이탈 → 0.80 스핀). 시드 1개의 우연이 결과를 지배한다.

**다음 단계 (순서대로)**
1. MPPI 시드 5개로 정답 μ MPC만 돌려 실패율을 잰다.
2. MPPI 안정화: 후보 수 증가(256 → 1024), 잡음을 시간 방향으로 매끄럽게(저역 통과), 예측 길이 1.0 → 1.5초, 방식 B 가장자리 여유 확대. 정답 μ MPC가 모든 장면에서 5/5 완주할 때까지 조정하고 고정한다.
3. 그 뒤 학습 모델을 같은 설정·시드 5개로 돌려 비교한다.

**다시 돌리는 방법**
```
python -m control.run_scene --mode A --ctrl pp mppi_dry mppi_oracle mppi_b1 mppi_m0 mppi_m1 mppi_m2 mppi_m3
python -m control.run_scene --mode B --ctrl mppi_dry mppi_oracle mppi_b1 mppi_m0 mppi_m1 mppi_m2 mppi_m3
python -m control.mpc_video --mode A --layout single     # 한 화면 영상 (panels: 모델마다 칸)
python -m control.rerun_mpc                              # Rerun 분석 기록
```
- 제어기마다 따로 돌린 뒤 그림만 다시 그리려면 `--threads 1 --no-plot`으로 하나씩 돌리고 `--reuse`로 모은다.
- 결과는 `viz/out/mpc/<제어기>_<A|B>[_tag].npz`에 저장된다.
