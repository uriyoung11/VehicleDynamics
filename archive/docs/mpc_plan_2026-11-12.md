# MPC 도입 검토 (11/12)

> 11/16 이후 실험 설계와 결과는 [mpc_comparison_design_2026-11-16.md](mpc_comparison_design_2026-11-16.md)에 있다. 이 문서는 도입 검토 당시 기록이다.

지금 시각화 장면은 차가 무엇으로 움직이는지, 제어기를 MPC로 바꾸면 무엇이 좋아지고 어떤 비교가 가능한지, 쓸 수 있는 MPC 도구는 무엇인지를 정리한다. project.md의 RQ5("예측 정확도 순위가 MPC 경로 추종 성능 순위와 같지 않을 수 있다")와 일정(12/7~12/27 NMPC 폐루프 실험)의 사전 검토다.

## 요약

1. **지금 장면에서 차를 모는 것은 학습 모델이 아니다.**
   - 조향은 기하학적 경로 추종(pure pursuit)이 정한다.
   - 속도는 미리 계산한 속도표를 P 제어로 따라간다.
   - M0와 B1은 옆에서 "1초 뒤를 예측만" 하는 관찰자다.
   - 그래서 지금 시각화는 **모델의 예측 차이**(1초 궤적이 실제와 얼마나 벌어지나, 11/7에 정한 주 지표)는 보여 준다. 예: 젖은 노면 진입 때 M0 77 cm, B1 14 cm.
   - 하지만 **그 예측으로 운전했을 때의 결과 차이**(이탈하나, 미리 감속하나)는 보여 주지 못한다. 어떤 모델이든 차는 똑같이 달리기 때문이다.
2. **MPC로 바꾸면 모델이 주행을 결정한다.** 그래서 "예측을 잘하는 모델이 실제로 더 잘 달리게 하는가"를 직접 잴 수 있다(RQ5). 젖은 노면에서 미리 속도를 줄이는지도 볼 수 있다.
3. **추천 순서**
   1. **MPPI(PyTorch)로 시작한다.** 우리 모델이 전부 PyTorch라 고치지 않고 바로 넣을 수 있다.
   2. 정밀 비교는 **CasADi(+ acados)** 기울기 기반 NMPC로 한다.
4. **먼저 풀어야 할 문제:** 지금 모델은 r과 Uy만 예측하고 Ux(종속도)는 예측하지 않는다. MPC에는 Ux 예측이 필요하다.

## 1. 지금 시각화의 주행 방식

코드: [viz/demo_track.py](../../viz/demo_track.py)의 `speed_profile`, `simulate`

| 부분 | 지금 방식 | 설명 |
|---|---|---|
| 차량·물리 | `f1tenth` 프리셋, P2 모델(Pacejka, 하중 이동, 결합 슬립 derate) | "실제 차" 역할. 1 ms 간격 RK4로 적분 |
| 노면 | 마른 노면 μ 0.70, 가장 빠른 코너 근처 25 m만 젖은 노면 μ 0.55 | |
| 속도 계획 | 곡률로 정한 한계 속도 √(k·μ·g/κ)에 가감속 한계를 적용(k = 0.75) | **마른 노면 μ로만** 계획한다. 젖은 구간을 모른다 |
| 조향 | pure pursuit: 속도에 비례해 앞을 보고(1.0 + 0.5·Ux m) 그 점을 향해 조향 | 차의 동역학(미끄러짐, 타이어 한계)을 전혀 모른다 |
| 종방향 | 목표 속도와의 차이에 비례하는 P 제어 + 주행 저항 보상 | |
| 학습 모델(M0, B1) | 기록된 상태를 보고 1초 뒤 r, Uy를 예측. Ux, 조향, 구동력은 실제 값을 넣는다 | 주행에는 쓰이지 않음. 예측 궤적을 실제와 비교만 한다 (개루프 평가) |

장면에서 차가 트랙을 벗어나는 이유: 속도 계획은 마른 노면 기준인데 젖은 구간에서 접지력이 21% 줄어든다. pure pursuit는 미끄러짐을 모르므로 미리 감속하지 못한다. 의도한 시나리오다.

## 2. MPC란

MPC(모델 예측 제어)는 매 순간 다음을 반복한다.

1. 차량 모델로 앞으로 1~2초 동안 여러 조향·가속 계획을 시뮬레이션한다.
2. 경로 오차, 속도, 트랙 이탈, 조작량 크기를 합친 비용이 가장 작은 계획을 고른다.
3. 그 계획의 첫 동작만 실행하고 다음 순간 다시 계산한다.

핵심은 **모델이 제어 루프 안에 들어간다**는 점이다. 모델이 좋으면 계획이 맞아떨어지고, 나쁘면 계획과 실제가 어긋난다.

## 3. MPC로 바꿀 때의 장점

**연구 측면**
- **RQ5를 직접 검증한다.** 같은 MPC에 모델만 바꿔 넣고 폐루프 성능(이탈, 경로 오차, 랩타임)을 비교한다. 지금은 개루프 예측 오차만 볼 수 있다.
- **한계 주행을 "의도해서" 할 수 있다.** 마찰원 제약(|a| ≤ μg)과 트랙 경계를 제약으로 넣으면 한계 근처를 일부러 쓰는 주행이 나온다. pure pursuit는 속도표에 의존한다.
- **"μ 모름" 주 실험(11/7 결정)과 바로 연결된다.**
  - μ를 아는 MPC, 모르는 MPC, 추정하는 MPC를 비교할 수 있다.
  - 젖은 구간에 들어갔을 때 모델이 접지력 변화를 알아채고 감속하는지 볼 수 있다.
- **불확실성 실험과 연결된다.** 예측 분산이 큰 모델이 더 보수적으로 달리게 할 수 있다(Spielberg 박사논문의 문제의식).

**시각화 측면**
- 지금 화면의 "예측 궤적"은 관찰자의 추측이다. MPC에서는 **차가 실제로 따르려는 계획**이 된다.
  - 계획과 실제가 벌어지는 순간이 곧 모델이 틀린 순간이다.
  - 발표에서 "모델이 틀리면 차가 이렇게 된다"를 바로 보여 줄 수 있다.
- 같은 장면을 모델만 바꿔 여러 번 돌려 나란히 놓을 수 있다. 예: "M0가 몬 차는 이탈, B1이 몬 차는 감속 후 통과".

## 4. 가능한 비교 실험

| 실험 | 바꾸는 것 | 고정하는 것 | 지표 |
|---|---|---|---|
| **A. 모델 교체 (RQ5 핵심)** | MPC 안의 모델: 정답 물리(P2, 상한선), P1 공칭, B1, M0, M1, M2, M3 | MPC, 비용, 트랙, μ | 이탈 횟수·최대 이탈 거리, 횡방향 오차 RMS, 랩타임, 계획 대비 실제 오차 |
| B. 예측 순위 vs 제어 순위 | A의 결과 | | 개루프 1초 오차 순위와 폐루프 성능 순위의 상관 |
| C. μ 정보 | μ 정답 제공 / 마른 노면 값 고정 / 온라인 추정 | 모델 | 젖은 구간 이탈, 감속 시작 시점 |
| D. 공격성 스윕 | 속도 목표 또는 마찰 사용률 0.6~1.1 | 모델 | 몇 %에서 처음 이탈하는가 (모델별 "안전 한계") |
| E. 제어기 비교 | pure pursuit, Stanley, LQR, 운동학 MPC, 동역학 NMPC | 정답 물리 | 같은 장면 결과. MPC가 필요한 이유를 보여 준다 |
| F. 계산 시간 | 모델 크기, 예측 구간 길이 | | 한 번 풀이 시간 (실시간 50 Hz 가능 여부) |

**공정성 규칙:** 비용 함수, 예측 구간, 제약, 튜닝 값은 모든 모델에서 같게 둔다. 튜닝은 정답 물리(P2)로 한 번만 하고 고정한다.

## 5. 쓸 수 있는 MPC

| 방식 | 도구 | 우리 모델 연결 | 장점 | 단점 |
|---|---|---|---|---|
| **샘플링 MPC (MPPI)** | [pytorch_mppi](https://github.com/UM-ARM-Lab/pytorch_mppi) 또는 직접 구현 (100줄 안팎) | PyTorch 모델을 **그대로** 사용 | 미분이 필요 없다. 비볼록 비용과 트랙 경계를 그냥 넣는다. 모든 모델을 같은 코드로 비교할 수 있다 | 샘플 수에 따라 결과가 흔들린다. CPU에서 샘플 수백 × 구간 수십을 매 스텝 돌려야 해 느릴 수 있다 |
| **기울기 기반 NMPC** | [CasADi](https://web.casadi.org/) + IPOPT | 물리 모델은 CasADi 식으로 다시 쓴다. 신경망은 [l4casadi](https://github.com/Tim-Salzmann/l4casadi)로 PyTorch → CasADi | 결과가 결정적이고 제약을 정확히 다룬다. 논문 표준 | 느리다(IPOPT). 신경망을 넣으면 더 느리다 |
| 고속 NMPC | [acados](https://github.com/acados/acados) (+ CasADi), 학습 모델은 [L4acados](https://arxiv.org/html/2411.19258v2) | CasADi와 같음 | 실시간 레이싱 MPC의 사실상 표준(SQP-RTI) | Windows 빌드가 까다롭다(WSL 권장). 설정할 것이 많다 |
| 선형화 MPC (LTV-MPC) | [OSQP](https://osqp.org/) 또는 CVXPY | 매 스텝 PyTorch로 모델을 선형화(자코비안)해 QP를 푼다 | 빠르고 안정적이다. 미분 가능한 우리 모델과 잘 맞는다 | 한계 근처의 강한 비선형을 놓칠 수 있다 |
| MPC 프레임워크 | [do-mpc](https://www.do-mpc.com/) | CasADi 기반 | 예제와 문서가 많다 | 내부는 결국 CasADi + IPOPT |

- [ForzaETH race stack](https://github.com/ForzaETH): F1TENTH 실차 레이싱 스택. 제어기와 타이어 식별 코드가 공개돼 있다.
- [TUMFTM](https://github.com/TUMFTM): 레이싱 라인 최적화(global_racetrajectory_optimization), Roborace 제어 코드(MATLAB).
- 원논문 계열: Spielberg 박사논문(신경망 MPC), Broadbent AVEC '24(신경망 타이어 + 드리프트 NMPC).

## 6. 우리 모델을 MPC에 넣을 때 풀어야 할 문제

1. **Ux를 예측하지 않는다.** 지금 모델(Spielberg 형식)은 [r, Uy]만 예측하고, 롤아웃에서도 Ux는 실제 값을 쓴다. MPC는 Ux도 스스로 예측해야 한다. 선택지는 둘이다.
   - Ux는 간단한 물리식(m·dUx/dt = Fx − 저항 + m·r·Uy)으로 두고, 모든 모델에 같은 식을 쓴다. **비교가 공정해서 추천한다.**
   - 모델 출력에 Ux를 추가하고 다시 학습한다.
2. **입력이 과거 4스텝 이력이다.** MPC 상태에 과거 이력을 같이 들고 다녀야 한다. MPPI는 문제없고, CasADi는 상태 차원이 늘어난다.
3. **시간 간격.** 모델은 10 ms 간격인데, 1초를 보려면 100스텝이라 MPC에는 너무 많다. 모델을 여러 번 반복해 20~50 ms 단위로 묶거나 예측 구간을 줄여야 한다.
4. **계산 시간.** 실시간이 목표는 아니므로 시뮬레이션에서는 느려도 된다. 다만 결과 보고에 풀이 시간을 같이 적는다.
5. **학습 분포 밖.** MPC는 모델의 약점을 파고드는 계획을 고를 수 있다(학습 데이터에 없던 조합). 이것 자체가 RQ5에서 보려는 현상이니 기록해 둔다.
