# 11/17 정리: Golf 시뮬레이터, Thunderhill West 트랙, 여러 차 데이터 섞어 학습하기

**정한 것 (11/17 회의):** 주 차량은 **VW Golf**, 데이터는 **D7** (Stanford 2025, [purl.stanford.edu/hh613qz0317](https://purl.stanford.edu/hh613qz0317)), MPC는 **MPPI**.

이 결정에 맞춰 오늘 세 가지를 했다.

| | 한 줄 요약 |
|---|---|
| Golf 시뮬레이터 | 공개 제원이 없어 D7 주행 기록으로 추정했다. 기록과 비교하면 2초 뒤까지 잘 맞는다 |
| 트랙 | 지도(OpenStreetMap)의 실제 노면 중앙선 + D7 주행으로 Thunderhill West 경계를 만들었다 |
| 섞어 학습하기 | GTI(D1) 데이터를 Golf(D7)와 섞으면 Golf 예측이 더 좋고 안정적이다. 가장 좋은 모델은 M1 |

## 1. Golf 시뮬레이터

### 왜 필요한가
MPPI로 "학습한 모델이 차를 운전하는" 시험을 하려면, MPPI가 낸 조향·가속에 차가 어떻게 반응하는지 계산해 줄 **가짜 실제 차(시뮬레이터)**가 있어야 한다. D7은 이미 끝난 주행 녹화라서, 녹화에 없는 조작에는 답을 못 한다.

### 제원을 찾아봤지만 없었다
- D7 데이터셋 페이지에는 차량 제원(무게, 무게중심, 관성, 타이어 특성)이 없다.
- 이 데이터를 쓴 논문(Mori 외 2025)은 아직 공개되지 않은 것으로 보인다.
- D1의 GTI와는 다른 차다(앞 브레이크 비율이 0.75 vs 0.66).

### 그래서 데이터로 추정했다 (`physics/golf_sysid.py`)
- **고정한 값:** 무게 1630 kg (브레이크 힘과 감속도로 계산), 앞뒤 바퀴 사이 거리 2.63 m (제조사), 무게중심은 앞쪽 60% (제조사 기준)
- **데이터에 맞춘 값:** 회전 관성, 앞뒤 타이어 특성, 노면 마찰계수(μ 1.09), 무게중심 높이, 주행 저항
- **맞추는 방법:** 기록된 조향과 페달 힘을 시뮬레이터에 넣고 0.5초 동안 굴려서, 실제 기록과 차이가 가장 작아지게 했다.
  - 한 순간(0.01초)만 맞추면 값이 비현실적으로 나온다. 우리 M1과 팀원 R1에서 둘 다 확인한 문제다.

### 얼마나 맞나
학습에 안 쓴 Golf 주행 3개에, 기록된 조작만 넣고 2초 굴렸을 때의 오차다.

| | 회전 속도 r [rad/s] | 옆 미끄러짐 속도 Uy [m/s] |
|---|---|---|
| **Golf 시뮬레이터** | **0.052** | **0.42** |
| GTI 제원을 그대로 쓰면 | 0.219 | 3.40 |
| 지금 값을 그대로 유지한다고 치면 | 0.263 | 0.75 |

데이터에서 계산한 타이어 힘-미끄러짐 관계와도 잘 맞는다 ([그림](figures/golf_tire_fit.png)). 시뮬레이터는 `physics.params`의 `golf` 프리셋으로 등록했다.

### 남은 문제
- **한계 근처 확인 필요:** 같은 조향각에서 비교하면 시뮬레이터의 최대 횡가속도가 데이터보다 낮게 나온다(0.83 g vs 0.94 g). 비교 방식 차이일 수 있다. 시뮬레이터가 실제보다 덜 붙으면 D7로 학습한 모델이 그 안에서 과속하게 되므로, MPPI 비교 전에 다시 확인한다.
- **정확한 값은 아님:** 무게중심 위치는 데이터로 정해지지 않았고, 회전 관성과 공기 저항은 일반 Golf보다 크게 나왔다. 정확한 제원은 데이터셋 저자에게 문의해야 알 수 있다.

## 2. Thunderhill West 트랙 (`data/thunderhill_west.py`)

### 왜 만들었나
D7에는 트랙 경계 파일이 없다. D1 자료의 Thunderhill 경계는 다른 코스(본 코스)라서 쓸 수 없다.

### 어떻게 만들었나
- **중앙선:** OpenStreetMap에 그려진 Thunderhill West의 실제 노면 중앙선을 썼다. D7 위치와 같은 좌표계라 2 m 안으로 겹친다.
- **폭:** 지도에 폭 정보가 없어서 D7 주행으로 추정했다. 레이싱 라인은 코너에서 가장자리 근처까지 가므로, "레이싱 라인이 중앙선에서 벗어난 최대 거리 + 차 반폭"을 그쪽 폭으로 잡았다. 레이싱 라인이 안 가는 쪽은 Thunderhill 본 코스 폭(8.8 m) 기준으로 최소 4.4 m.

### 결과 ([그림](figures/thunderhill_west.png))
- 한 바퀴 **2,666 m**, 폭은 대부분 **8.8~9.7 m**
- D7의 실제 주행 위치가 모두 경계 안에 들어온다.
- 공식 West 코스(3.2 km)보다 짧은데, 짧은 판 코스(약 2.65 km)와 길이가 맞는다.

### 한계
- 공식 노면 경계가 아니다. 레이싱 라인이 가지 않은 쪽은 실제보다 좁을 수 있다(MPPI에는 조심스러운 쪽으로 작용).
- 지도 선이 몇 곳에서 꺾여 있다.

## 3. GTI와 Golf 데이터를 섞어 학습하기 (1단계 실험)

### 무엇을 했나
같은 모델(B1, M0~M3)을 네 가지 데이터로 학습하고, Golf 시험 데이터에서 1초 뒤 예측 오차를 비교했다(시드 2개).

- **GTI만:** D1
- **Golf만:** D7
- **그냥 섞기:** D1 + D7
- **차 구분 표시를 붙여 섞기:** 입력에 "GTI/Golf" 표시를 추가

### 결과 (Golf 시험, 1초 롤아웃 오차, 작을수록 좋음, 시드 0 / 1)
학습 없이 "지금 값이 유지된다"고 예측해도 **0.62**다.

| 학습 데이터 | B1 (물리) | M0 (신경망) | **M1 (물리+보정)** | M3 (PINN) |
|---|---|---|---|---|
| GTI만 | 0.49 / 0.50 | 0.53 / 0.54 | 22 / 29 (발산) | 1.02 / 0.50 |
| Golf만 | 0.42 / 0.42 | 1.12 / 4.90 | 0.33 / 0.42 | 1.52 / 3.33 |
| **그냥 섞기** | 0.42 / 0.43 | 0.31 / 2.44 | **0.32 / 0.32** | 0.30 / 0.27 |
| 차 구분 표시 | – | 0.46 / 0.40 | 0.33 / 0.41 | 0.52 / 0.84 |

M2는 대부분 0.6~2.5로 기준선보다 나빠서 표에서 뺐다. 전체 결과는 [mixing_io_format_2026-11-17.md](mixing_io_format_2026-11-17.md) 3절.

### 알게 된 것
1. **섞으면 좋아진다.** M1은 Golf만 쓸 때 0.33 / 0.42에서, 섞으면 0.32 / 0.32로 더 좋고 시드 차이도 사라진다. GTI 시험에서도 가장 좋다(0.27 / 0.26).
2. **다른 차 데이터로만 학습하면 위험하다.** GTI로만 학습한 M1은 Golf에서 발산했다. 단순한 물리 모델(B1)과 신경망(M0)은 버텼다.
3. **차 구분 표시는 쓸모가 없었다.** 두 차가 매우 비슷해서 구분할 이득이 없었던 것으로 본다.
4. **모델마다 안정성이 다르다.**
   - M1이 가장 안정적이다.
   - M3는 잘 될 때는 가장 좋지만 자주 발산한다.
   - M0는 시드(초기값)에 따라 결과가 크게 갈린다.
5. **실제 단위로 보면** 섞은 M1의 1초 뒤 오차는 회전 속도 0.034 rad/s, 옆 미끄러짐 속도 0.36 m/s다. 기준선(0.152, 0.474)보다 각각 4.5배, 1.3배 정확하다.
